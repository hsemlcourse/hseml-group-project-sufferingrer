## 1. Введение и постановка задачи

**Цель проекта:** автоматически определять тональность пользовательских отзывов на товары (позитивный / нейтральный / негативный). Практическая ценность — помочь селлерам на маркетплейсах быстро обрабатывать входящие отзывы и отвечать на них по шаблону без ручной сортировки.

**Формулировка задачи:** многоклассовая классификация (3 класса: 0 — негативный, 1 — нейтральный, 2 — позитивный).

**Метрика:** Macro F1. Датасет сбалансирован (по 33% на класс), поэтому Accuracy тоже валидна. Выбрал Macro F1, потому что в реальных отзывах Ozon классы несбалансированы — негативных меньше, и важно не игнорировать ни один класс. Macro F1 одинаково штрафует за ошибки на каждом классе независимо от его размера, поэтому она надёжнее для продакшна.

## 2. Поиск и описание данных

**Источник:** [ai-forever/ru-reviews-classification](https://huggingface.co/datasets/ai-forever/ru-reviews-classification) на HuggingFace. Выбрал потому что это готовый размеченный датасет русскоязычных отзывов на товары — именно то что нужно для задачи. Альтернативой был парсинг Ozon, но это дополнительный этап (запланирован отдельно).

**Описание датасета:**
- Объём: 60 000 строк, 2 столбца (`text`, `label`)
- `text` — текст отзыва на русском языке
- `label` — тональность: 0 (негативный), 1 (нейтральный), 2 (позитивный)
- Классы строго сбалансированы: по 20 000 примеров на каждый

## 3. Обработка и подготовка данных

**Очистка:**
- Пропуски: отсутствуют (датасет с HuggingFace чистый)
- Дубликаты: проверены по полю `text`, удалены если найдены
- Выбросы по длине текста: проверен 99-й перцентиль. Очень длинные отзывы оставлены — трансформер обрежет до 512 токенов автоматически, для TF-IDF это тоже не критично
- Типы данных: `text` — строка, `label` — int, приведение не требовалось

**Работа с фичами:**
- Исходных признаков: 1 (`text`)
- Добавлено 7 числовых признаков:
  - `feat_char_len` — длина текста в символах
  - `feat_word_count` — количество слов
  - `feat_upper_ratio` — доля заглавных букв (сигнал эмоциональности)
  - `feat_exclamation_count` — количество `!`
  - `feat_question_count` — количество `?`
  - `feat_emoji_count` — количество эмодзи
  - `feat_avg_word_len` — средняя длина слова

**Нормализация текста:** lower, удаление HTML-тегов и URL, нормализация пробелов. Эмодзи и пунктуацию оставил — они несут сентимент-сигнал (💩 = neg, ❤️ = pos).

**Визуализации:** распределение классов, длины текстов по классам, топ-20 слов по каждому классу (см. `data/processed/`).

**Сплит:**
- Test (holdout) взят из оригинального сплита датасета — не трогается до финальной оценки
- Из train: 85% train / 15% val, стратифицированный по `label`, `random_state=42`
- Даталика нет: тексты независимы, временной зависимости нет, random split корректен

## 4. Baseline-модель

**Модель:** Logistic Regression + TF-IDF (без feature engineering, из коробки)

**Параметры:** `TfidfVectorizer(max_features=50000, ngram_range=(1,2), sublinear_tf=True)`, `LogisticRegression(C=1.0, max_iter=1000)`

**Результат на val:**

| Модель | Val Macro F1 |
|---|---|
| LogReg + TF-IDF | 0.7481 |

Baseline 0.75 — хорошая точка отсчёта для трёхклассовой задачи.

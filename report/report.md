## 1. Введение и постановка задачи

**Цель проекта:** автоматически определять тональность пользовательских отзывов на товары (позитивный / нейтральный / негативный). Практическая ценность — помочь продавцам на маркетплейсах быстро обрабатывать входящие отзывы и отвечать по готовому шаблону без ручной сортировки.

**Формулировка задачи:** многоклассовая классификация (3 класса: 0 — негативный, 1 — нейтральный, 2 — позитивный).

**Обоснование метрики:** выбрал Macro F1. Датасет сбалансирован (по 33% на класс), поэтому Accuracy тоже валидна, но в реальных отзывах на маркетплейсах негативных значительно меньше. Macro F1 одинаково штрафует за ошибки на каждом классе независимо от его размера — это важно для продакшна, где пропустить негативный отзыв хуже, чем ошибиться с нейтральным.

## 2. Поиск и описание данных

**Источник:** [ai-forever/ru-reviews-classification](https://huggingface.co/datasets/ai-forever/ru-reviews-classification) на HuggingFace. Выбрал потому что это готовый размеченный датасет русскоязычных отзывов на товары с тремя классами тональности — именно то что нужно для задачи.

**Описание датасета:**
- Объём: 60 000 строк, 2 столбца
- `text` — текст отзыва на русском языке (строка)
- `label` — тональность: 0 (негативный), 1 (нейтральный), 2 (позитивный) (целое число)
- Классы строго сбалансированы: по 20 000 примеров на каждый (33.3%)

---

## 3. Обработка и подготовка данных

**Полная очистка:**
- Пропуски: отсутствуют — датасет с HuggingFace уже чистый
- Дубликаты: проверены по полю `text`, обнаружены и удалены
- Выбросы по длине текста: проверен 99-й перцентиль. Очень длинные отзывы оставлены — для TF-IDF это не критично, а трансформер обрежет до 512 токенов автоматически
- Типы данных: `text` — str, `label` — int, приведение не требовалось

**Работа с фичами:**
- Исходных признаков: 1 (`text`)
- Добавлено 7 числовых признаков: `feat_char_len`, `feat_word_count`, `feat_upper_ratio`, `feat_exclamation_count`, `feat_question_count`, `feat_emoji_count`, `feat_avg_word_len`
- Нормализация текста: lower, удаление HTML-тегов и URL, нормализация пробелов. Эмодзи и пунктуацию оставил — они несут сентимент-сигнал

**Визуализации:** распределение классов, гистограммы длин текстов по классам, топ-20 слов по каждому классу, SVD 2D визуализация пространства признаков (см. `data/processed/`)

**Сплит данных:**
- Test (holdout) взят из оригинального сплита датасета — не использовался до финальной оценки
- Из train: 85% train / 15% val, стратифицированный по `label`, `random_state=42`
- Даталика нет: тексты независимы, временной зависимости нет, random split корректен

## 4. Baseline-модель

**Модель:** Logistic Regression + TF-IDF без feature engineering, из коробки

**Параметры:** `TfidfVectorizer(max_features=50000, ngram_range=(1,2), sublinear_tf=True)`, `LogisticRegression(C=1.0, max_iter=1000)`

**Результаты на val:**

| Метрика | Значение |
|---|---|
| Macro F1 | 0.7487 |
| Accuracy | ~0.75 |

**Цель:** точка отсчёта для сравнения с более сложными моделями.

---

## 5. Эксперименты

Перебор гиперпараметров: GridSearchCV по C=[0.1, 1.0, 5.0, 10.0], 3-fold CV, scoring=f1_macro.

Уменьшение размерности: TruncatedSVD (LSA) на 100 и 300 компонентах с визуализацией в 2D.

| Модель | Гипотеза | Параметры | Val Macro F1 | Комментарий |
|---|---|---|---|---|
| Baseline: LogReg + TF-IDF | Точка отсчёта | C=1.0, ngram(1,2), 50k | 0.7487 | — |
| LogReg GridSearch | Подбор C улучшит baseline | C=0.5, class_weight=balanced | **0.7488** | Лучшая модель |
| Voting (LogReg+LightGBM+CatBoost) | Ансамбль даст прирост | soft voting | 0.7483 | Чуть хуже одиночной |
| LogReg + Word+Char TF-IDF | Char n-граммы ловят морфологию | word(1,2)+char_wb(3,6) | 0.7438 | Хуже word-only |
| LinearSVC (calibrated) | SVM создан для разреженных данных | C=1.0 | 0.7361 | Хуже LogReg |
| CatBoost | Бустинг лучше логрегрессии | iter=500-800, depth=6-8 | 0.7294 | Деревья хуже на TF-IDF |
| LightGBM | Бустинг лучше RF | n=500-800, leaves=63-127 | 0.7227 | То же |
| Random Forest | Ансамбль деревьев лучше LogReg | n=200, balanced | 0.7165 | Деревья плохо на разреженных |
| SVD(300) + LogReg | SVD выделит темы | n_components=300 | ~0.72 | Потеря при сжатии |
| SVD(100) + LogReg | SVD выделит темы | n_components=100 | ~0.70 | Сильная потеря |
| KNN (cosine) | Похожие тексты → одна тональность | k=7, cosine | 0.6621 | Плохо в высокой размерности |

**Вывод по экспериментам:** линейные модели (LogReg, LinearSVC) стабильно лучше деревьев на разреженных TF-IDF матрицах. Ансамбль не дал прироста над одиночной моделью — модели коррелируют в ошибках. Char n-граммы не помогли — word-level достаточно. SVD ожидаемо теряет качество при сжатии.

## 6. Финальная модель и интерпретируемость

**Финальная модель:** LogReg GridSearch, `C=0.5, class_weight='balanced'`, TF-IDF `ngram(1,2), max_features=50k`

**Обоснование:** лучший Val Macro F1 = 0.7488. Простая, интерпретируемая, быстро предсказывает — подходит для продакшна. Ансамбль дал такой же результат при большей сложности.

**Интерпретируемость (коэффициенты LogReg):**
- Негативный класс: топ-слова — "брак", "сломался", "вернул", "ужасно", "не работает"
- Нейтральный класс: топ-слова — "нормально", "ничего", "обычный", "средне"
- Позитивный класс: топ-слова — "отлично", "рекомендую", "доволен", "качество", "спасибо"

Коэффициенты интерпретируются напрямую: чем выше значение для слова, тем сильнее оно сигнализирует принадлежность к классу. Визуализация — см. `data/processed/feature_importance.png`.

## 7. Деплой

**Интерфейс:** Streamlit — пользователь вставляет текст отзыва, получает тональность с уверенностью модели и готовый шаблон ответа.

**API:** FastAPI

| Эндпоинт | Метод | Описание |
|---|---|---|
| `/` | GET | Статус сервиса |
| `/health` | GET | Проверка загрузки модели |
| `/predict` | POST | Классификация отзыва |

Пример запроса:
```bash
curl -X POST http://localhost:8000/predict \
     -H "Content-Type: application/json" \
     -d '{"text": "Отличный товар, очень доволен покупкой!"}'
```

Пример ответа:
```json
{
  "label": 2,
  "sentiment": "positive",
  "confidence": 0.9134
}
```

**Запуск через Docker:**
```bash
docker-compose up --build
# API:       http://localhost:8000
# Swagger:   http://localhost:8000/docs
# Streamlit: http://localhost:8501
```

## 8. Заключение и выводы

**Итоги:** лучший Val Macro F1 = 0.7488 (LogReg GridSearch). Прирост над baseline (0.7487) минимален — baseline уже близок к потолку для TF-IDF подхода на этом датасете. Деплой реализован через FastAPI + Streamlit + Docker.

**Ограничения:**
- TF-IDF не учитывает порядок слов и контекст — "не понравилось" и "понравилось" обрабатываются похоже
- Нейтральный класс сложнее всего — граница между neg/neutral и neutral/pos размытая
- Модель обучена на сбалансированном датасете, реальные отзывы Ozon — несбалансированы

**Возможные улучшения:**
- Fine-tuning rubert-tiny2 — ожидаемо даст +5-10% F1 за счёт понимания контекста
- Парсинг реальных отзывов Ozon для дообучения на доменных данных
- Добавление модуля автоответов: классификатор → выбор шаблона → LLM для персонализации ответа
